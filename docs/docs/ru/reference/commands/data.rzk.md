# Команда `#data`

Команда `#data` объявляет индуктивный тип: формирователь типа, его конструкторы и порождённые элиминаторы.

## Синтаксис

```{.rzk}
#data <name> [uses (<vars>)] (<param>)* := <constructor> [| <constructor>]*
#data <name> [uses (<vars>)] (<param>)*
```

где конструктор имеет вид

```{.rzk}
<name> (<field>)*
```

## Описание

Объявление вводит формирователь типа, по одному обычному имени верхнего уровня на конструктор и два порождённых элиминатора: принцип индукции `ind-<name>` и его не зависимую версию `rec-<name>`. Все они живут в одном пространстве имён с остальными именами верхнего уровня, поэтому совпадение с существующим именем — ошибка. Вторая форма (без `:=`) объявляет пустое семейство.

Например:

```rzk
#lang rzk-1

#data bool := false | true

#data coprod
  ( A B : U)
  :=
    inl (a : A)
  | inr (b : B)
```

порождает

```rzk
#check ind-bool : (C : bool → U) → C false → C true → (b : bool) → C b
#check rec-coprod
  : ( A : U) → (B : U) → (C : U)
  → ( ( a : A) → C) → ((b : B) → C)
  → coprod A B → C
```

Аргументы элиминатора идут в порядке: параметры, мотив, по одному методу на конструктор (в порядке объявления), устраняемое значение. Вычисление определительное: элиминатор, применённый к конструктору, вычисляется в соответствующий метод, применённый к полям конструктора.

!!! warning "Большие индуктивные типы"

    Поле конструктора, чей тип является вселенной или квантифицирует по ней (например, `#!rzk box (X : U)`), делает тип _большим_. Поскольку в Rzk сейчас `#!rzk U : U`, большой индуктивный тип — известный короткий путь к противоречию, поэтому объявление принимается с предупреждением.

## Текущие ограничения

На данный момент `#data` поддерживает только нерекурсивные объявления:

- поля конструкторов не могут упоминать объявляемый тип (рекурсивные типы, такие как натуральные числа, запланированы);
- сортом может быть только `#!rzk U`, а явно указанный тип результата конструктора должен быть объявляемым типом, применённым к параметрам (индексированные семейства запланированы);
- конструкторы не могут принимать аргументы-кубы и аргументы-формы (над направленным интервалом они объявляли бы направленные клетки);
- клауза `eliminator` разбирается парсером, но пока не поддерживается.

Отметим также, что индуктивный тип приходит ровно со своим принципом индукции; взаимодействие типа с симплициальной структурой — отдельный вопрос. См. предупреждение о дискретности в разделе [Зависимые типы](../../getting-started/dependent-types.rzk.md#booleans).
