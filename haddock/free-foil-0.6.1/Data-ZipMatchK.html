module Data.ZipMatchK.Mappings

class ZipMatchK (f :: k) where Source #

Kind-polymorphic syntactic (first-order) unification of two values.

Note that f is expected to be a traversable n-functor. There is no TraversableK constraint to say so at the moment.

The default implementation is generic, via RepK. It is convenient, but it reflects each node into a representation and back on every comparison, and a constructor is represented as a chain of L1/R1 wrappers as long as its index, so the cost grows with the size of the signature. Comparing terms is most of what a typechecker does, and on a large signature the generic instance costs roughly twice what the written-out one does. Use deriveZipMatchK (or deriveZipMatchK2, for a signature bifunctor with extra parameters) to generate the written-out instance instead.

Since: 0.2.0

Perform one level of equality testing:

  • when k = Type, values are compared directly (e.g. via Eq);
  • when k = Type -> Type, term constructors are compared. Unequal constructors give Nothing, and equal ones have all their components paired up with a given function.

class ZipMatchFoldK (f :: k) where Source #

Kind-polymorphic syntactic matching of two values that folds the paired components into a monoid instead of rebuilding the value.

zipMatchFoldK answers Nothing exactly when zipMatchWithK with functions that always succeed would: when the constructors differ, or a component compared by its own ZipMatchK differs. Otherwise it combines the folding functions applied to the paired components, left to right with <>. Nothing else is built, neither the matched value nor a pair per component, so a check of all components (with All, say) allocates nothing for the components and stops at the first one that fails.

The default implementation is generic, via RepK, with the costs described at ZipMatchK. deriveZipMatchK derives a written-out instance together with the one of ZipMatchK.

(ZipMatchFoldK ann, ZipMatchFoldK sig) => ZipMatchFoldK (AnnSig ann sig :: Type -> Type -> Type) Source #

Matching for AnnSig is derived, not left to the generic default.

The generic default would rebuild the Generics.Kind view of every node on every comparison, and comparing terms is most of what a typechecker does, so for an annotated signature, where it lands on the hottest path, that is a measurable cost. deriveZipMatchK2 generates the written-out instance instead: the annotation matched with the term zipper (an annotation is a functor of the term), and the inner signature with both. Write deriveZipMatchK2 ''YourAnnSig for a bespoke annotated signature.

Check a relation on all paired components: Nothing when the shapes differ, as for zipMatchFoldK, and otherwise whether every component satisfies its relation. The components are checked left to right, and the check stops at the first that fails.

zipMatchAllK = fmap getAll . zipMatchFoldK (coerce relations)

zipMatchFold2 :: (ZipMatchFoldK f, Monoid m) => (a -> a' -> m) -> (b -> b' -> m) -> f a b -> f a' b' -> Maybe m Source #

zipMatchFoldK specialised to bifunctors. With All it checks that two nodes have the same constructor and that their components satisfy a relation, without building anything for the components:

>>> import Data.Monoid (All (..))
>>> let same = zipMatchFold2 (\x y -> All (x == y)) (\x y -> All (x == y))
>>> getAll <$> same (Left 1) (Left (1 :: Int) :: Either Int Int)
Just True
>>> getAll <$> same (Left 1) (Left (2 :: Int) :: Either Int Int)
Just False
>>> getAll <$> same (Left 1) (Right (1 :: Int) :: Either Int Int)
Nothing
